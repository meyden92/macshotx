# Selection-first is the capture order

Supersedes [ADR 0013](0013-annotate-first-is-the-only-capture-order.md) and [ADR 0014](0014-commit-gesture-click-captures-drag-confirms.md). The capture overlay opens idle: the frozen screen, a helper card, the select tool and nothing else. A Selection is seeded by a drag, by a click on a window while window snap is armed, or by `F`, which fills it to the display under the cursor. None of them captures. Once a Selection exists the annotation tools come up around it, and it stays adjustable — Resolution box, handles, arrow-key nudge — until `Return` confirms it. `Return` is the only commit path in the overlay; with no Selection it does nothing, and `Esc` cancels. This is [ADR 0011](0011-every-route-seeds-a-selection.md)'s rule again, and the overlay of commit `1228b98` is the reference state, with everything added since that is not annotate-first kept and working inside the Selection.

Annotate-first was reversed because it confused the people using it. With every tool live and no Selection, nothing told the user what a click would do. A click on a window captured it, a click on empty space captured the whole display with no undo, a drag captured on release and `Return` captured the display — so a slip fired the shutter. And because no adjustable Selection ever existed in the overlay, the Resolution box, the handles and the nudge were unreachable there.

## Considered Options

- **Keep annotate-first as a setting** — rejected, for the reason ADR 0013 gave in the other direction: two orders means two meanings for a bare click and two helper cards, and every overlay feature afterwards has to ask what it does in the other order.
- **Keep the instant snap-click capture as a fast path** — rejected for ADR 0011's reasons. It is the capture most likely to want an arrow or a backdrop, and it is a single event, so it is the easiest one to fire by mistake.

## Consequences

- **The idle state is back.** While a capture overlay has no Selection, only the select tool exists: the tool strip and tool-options row are hidden, tool shortcuts are inert, and a tool chosen on another display is not adopted. The helper card shows, governed by "Show overlay hints", and says "select", never "capture". When the Selection goes away — dismissed by a click outside it, or taken by another display — the overlay returns to idle: the select tool comes back and post-processing switches off.
- **`F` means fullscreen only while idle.** With a Selection up it is the fill-rect tool, whose shortcut it is.
- **Select-tool click precedence, first match wins:** hits an annotation → select it; a selected set or an open text edit exists → clear it; a drawing tool is in hand → nothing; a Selection exists → a click outside dismisses it, inside or on a handle does nothing; snap is armed and a window is under the cursor → seed the Selection to that window; otherwise → nothing. No rung captures, and a bare click on empty space does nothing at all.
- **Select-tool drag precedence:** a selected annotation's handle or the selected set's outline → manipulate it; an annotation → grab it (Shift toggles membership); a Selection handle → resize; inside the Selection → move it, or with Command sweep the marquee; otherwise → draw a new Selection. The marquee is confined to the Selection again; a Command-drag outside it draws a Selection.
- **A Selection lives on one display, and starting one on another display clears the first** — by any route. ADR 0011 refused the single-event seeds (`F`, a snap click) while another display held the Selection. That is not kept: every idle display shows a helper card offering those routes, and a card that promises a click which then does nothing is worse than the slip it guards against. The cleared display keeps its annotations and returns to idle.
- `Return` on a display with no Selection does nothing, even while another display holds one. ADR 0014 forwarded it to that display; the forwarding went with `Return`-for-display.
- **Window snap still starts armed** on every capture, as ADR 0014 set it. Its highlight draws only while the overlay is idle, and `Tab` toggles it at any time. Capture hotkeys do not change that start ([ADR 0017](0017-capture-hotkeys-carry-a-pipeline.md)).
- The tool strip is never placed without a Selection. ADR 0013's bottom-of-the-display strip, and the session moving it to the display under the cursor, are deleted: the one strip is the one around the Selection, placed by the existing solver.
- Annotation happens inside an existing Selection, but a drawing tool still draws anywhere on the display. Moving or resizing the Selection afterwards clips with the compositor's bake-then-crop, unchanged.
- Post-processing previews against the Selection and is unavailable while idle (ADR 0007, amended).
- The post-capture editor is never idle. It annotates without a crop, exports the whole image when there is none, and keeps its own confirm.
- `%app` and `%window` name the frontmost app unless the Selection carries window provenance, which a snap seed gives it and any edit drops ([ADR 0018](0018-window-provenance-is-visible-and-drops-on-edit.md)).
